# CP-046: multi-agent system

![orchestration](../../assets/icons/orchestration.svg) ![intermediate](../../assets/badges/intermediate.svg) ![active](../../assets/badges/active.svg)

**Category:** `orchestration` | **Difficulty:** `intermediate` | **Confidence:** `high` | **Status:** `active` | **Verified:** `2026-11-11`

## Definition

An architecture where multiple specialized agents collaborate, compete, or delegate sub-tasks across distinct prompts, tools, or context windows.

## Why It Matters

Multi-agent division prevents context pollution, isolates privileges across roles, and parallelizes independent research branches.

## How It Works

Agents communicate via supervisor tool calls, structured handoffs, shared state graphs, or standardized wire protocols like A2A.

## Example

Separating a coding assistant into an isolated codebase researcher agent, an implementer agent, and a security reviewer.

## Common Mistakes

Splitting a simple cohesive workflow across numerous chattering agents, multiplying latency and failure points.
