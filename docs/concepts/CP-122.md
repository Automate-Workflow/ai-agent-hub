# CP-122: embedding privacy and inversion risk

![safety_and_security](../../assets/icons/safety-and-security.svg) ![advanced](../../assets/badges/advanced.svg) ![active](../../assets/badges/active.svg)

**Category:** `safety_and_security` | **Difficulty:** `advanced` | **Confidence:** `high` | **Status:** `active` | **Verified:** `2026-11-11`

## Definition

Security threat where stored dense text embeddings can be inverted back into sensitive source phrasing by adversarial decoders.

## Why It Matters

Organizing teams frequently store embeddings with weaker access controls than raw text, creating unexpected confidential leakage.

## How It Works

Inversion models iteratively reconstruct approximate input text from vector embeddings alone unless tenant access isolation is enforced.

## Example

Isolating sensitive HR and medical embeddings per tenant with encrypted storage and strict query authorization.

## Common Mistakes

Publishing shared or multi-tenant vector indices globally assuming vectors are irreversible one-way hashes.
