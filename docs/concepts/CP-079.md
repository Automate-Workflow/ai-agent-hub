# CP-079: agent identity

![safety_and_security](../../assets/icons/safety-and-security.svg) ![intermediate](../../assets/badges/intermediate.svg) ![active](../../assets/badges/active.svg)

**Category:** `safety_and_security` | **Difficulty:** `intermediate` | **Confidence:** `high` | **Status:** `active` | **Verified:** `2026-11-11`

## Definition

Cryptographically verifiable identity bindings distinguishing autonomous workloads, delegating human principals, and invoked external services.

## Why It Matters

Clear workload identity is necessary to enforce zero-trust authorization, attribution, and revocation across distributed systems.

## How It Works

Standards combining signed JWTs, OIDC, OAuth 2.1, and Agent Cards tie tokens to both the calling agent service and authorizing principal.

## Example

Attaching both agent workload ID and delegating user subject claims inside signed OAuth tokens.

## Common Mistakes

Letting autonomous services impersonate arbitrary users anonymously via shared service-wide keys.
