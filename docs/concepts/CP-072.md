# CP-072: permission scopes

![safety_and_security](../../assets/icons/safety-and-security.svg) ![intermediate](../../assets/badges/intermediate.svg) ![active](../../assets/badges/active.svg)

**Category:** `safety_and_security` | **Difficulty:** `intermediate` | **Confidence:** `high` | **Status:** `active` | **Verified:** `2026-11-11`

## Definition

Granular capability claims embedded in OAuth tokens or host policies enumerating exact resources and actions an agent may invoke.

## Why It Matters

Fine-grained scopes enable verifiable authorization checks independently of LLM prompt adherence.

## How It Works

Authorization servers mint tokens bearing explicit scope strings evaluated by resource APIs on every tool request.

## Example

Requesting `issues:read` scope for triage while separating `pull_requests:write` behind explicit approval.

## Common Mistakes

Using coarse catch-all admin scopes that lump destructive deletes alongside basic listing operations.
