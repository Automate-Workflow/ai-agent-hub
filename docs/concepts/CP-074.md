# CP-074: secrets management

![safety_and_security](../../assets/icons/safety-and-security.svg) ![beginner](../../assets/badges/beginner.svg) ![active](../../assets/badges/active.svg)

**Category:** `safety_and_security` | **Difficulty:** `beginner` | **Confidence:** `high` | **Status:** `active` | **Verified:** `2026-11-11`

## Definition

Architectural separation ensuring API keys, database passwords, and signing tokens live in host vaults and never enter LLM prompts or logs.

## Why It Matters

Keeping credentials outside model context prevents accidental leakage through prompt extraction, logging, or exfiltration attacks.

## How It Works

Host tool wrappers inject credentials at HTTP transport boundaries after validating LLM-supplied parameters.

## Example

Letting an agent reference a logical connection alias while the MCP host fetches the token from a secret manager.

## Common Mistakes

Passing raw API secrets in tool definitions, environment dumps, or debugging trace messages visible to models.
