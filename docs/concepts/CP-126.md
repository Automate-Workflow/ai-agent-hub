# CP-126: shadow testing and canary rollout

## Definition

Running updated agent versions silently in parallel or on small live traffic cohorts before general production cutover.

## Why It Matters

Shadow and canary rollouts isolate regression impact on real unpredictable user queries without exposing full traffic.

## How It Works

Production gateways mirror traffic to shadow pipelines or gradually shift percentages while alerting on schema, latency, or refusal spikes.

## Example

Shadow-testing a new system prompt on mirrored support traffic for three days before rollout.

## Common Mistakes

Directing shadow agent runs onto real side-effecting write APIs instead of mocked read-only endpoints.
