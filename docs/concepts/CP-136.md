# CP-136: corrective retrieval

**Category:** `memory_and_knowledge` | **Difficulty:** `intermediate` | **Confidence:** `high` | **Status:** `active` | **Verified:** `2026-11-11`

## Definition

Evaluating retrieved document relevance dynamically and triggering query rewrites, web fallback searches, or abstention when local knowledge lacks coverage.

## Why It Matters

Corrective retrieval prevents poor initial RAG searches from forcing hallucinated or stale answers.

## How It Works

An evaluator grades retrieved passages as correct, ambiguous, or incorrect, refining queries or falling back before generation.

## Example

Detecting missing local product patches via CRAG grading and rewriting the query before responding.

## Common Mistakes

Always forwarding top retrieved chunks to generation regardless of near-zero semantic relevance.
