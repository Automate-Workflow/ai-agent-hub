# CP-029: memory write-back

![memory_and_knowledge](../../assets/icons/memory-and-knowledge.svg) ![intermediate](../../assets/badges/intermediate.svg) ![active](../../assets/badges/active.svg)

**Category:** `memory_and_knowledge` | **Difficulty:** `intermediate` | **Confidence:** `high` | **Status:** `active` | **Verified:** `2026-11-11`

## Definition

Selecting, distilling, resolving conflicts in, and persisting new facts or experiences from active sessions into durable agent memory stores.

## Why It Matters

Controlled write-back preserves valuable user facts over time while rejecting transient noise and contradictory duplicates.

## How It Works

Dedicated extractors or reflection steps compare incoming observations against existing stored memories to add, update, or expire records.

## Example

Updating a stored workspace language preference from Java to TypeScript after explicit user confirmation.

## Common Mistakes

Unconditionally writing unverified third-party web content into long-term memory, risking persistent memory poisoning.
