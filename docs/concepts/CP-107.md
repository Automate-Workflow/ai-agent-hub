# CP-107: agent-facing API design

![tools_and_actions](../../assets/icons/tools-and-actions.svg) ![intermediate](../../assets/badges/intermediate.svg) ![active](../../assets/badges/active.svg)

**Category:** `tools_and_actions` | **Difficulty:** `intermediate` | **Confidence:** `high` | **Status:** `active` | **Verified:** `2026-11-11`

## Definition

Designing backend APIs, MCP tools, and documentation with explicit semantics, idempotency keys, pagination bounds, and descriptive errors for agents.

## Why It Matters

Clean API error messages guide agent self-correction without wasting retries on opaque failure codes.

## How It Works

Endpoints return actionable validation feedback explaining which parameter violated bounds and accept idempotent retry tokens.

## Example

Designing a lookup tool returning cursor-paginated summaries and actionable field hints when dates mismatch.

## Common Mistakes

Returning generic internal error strings or unbounded megabyte JSON lists to tool callers.
