# CP-039: reranking

![memory_and_knowledge](../../assets/icons/memory-and-knowledge.svg) ![intermediate](../../assets/badges/intermediate.svg) ![active](../../assets/badges/active.svg)

**Category:** `memory_and_knowledge` | **Difficulty:** `intermediate` | **Confidence:** `high` | **Status:** `active` | **Verified:** `2026-11-11`

## Definition

A second-stage relevance scoring step using cross-encoders or specialized rankers to reorder initial retrieval candidates accurately.

## Why It Matters

Reranking catches precise query-document relationships missed by fast first-stage vector dot products, boosting top-K precision.

## How It Works

After fast bi-encoder or hybrid search fetches candidate passages, a cross-encoder attends jointly over query-passage pairs to re-score.

## Example

Using a reranker model to promote exact API error troubleshooting chunks from candidate position twelve into top three.

## Common Mistakes

Passing too many unranked candidates directly to the generator instead of filtering down to top high-confidence chunks.
