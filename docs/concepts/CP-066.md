# CP-066: guardrails

![safety_and_security](../../assets/icons/safety-and-security.svg) ![beginner](../../assets/badges/beginner.svg) ![active](../../assets/badges/active.svg)

**Category:** `safety_and_security` | **Difficulty:** `beginner` | **Confidence:** `high` | **Status:** `active` | **Verified:** `2026-11-11`

## Definition

Deterministic and model-based runtime validation layers enforcing safety, schema, topic, PII, and policy boundaries on agent inputs and outputs.

## Why It Matters

Independent guardrail checks provide defense in depth even when core LLM prompts face adversarial inputs or edge failures.

## How It Works

Validators intercept inputs, tool calls, and responses along execution pipelines to block, redact, retry, or escalate violations.

## Example

Blocking responses containing leaked secret keys or unverified PII patterns before returning chat completions.

## Common Mistakes

Assuming guardrails eliminate all adversarial risk without underlying access controls and sandboxing.
