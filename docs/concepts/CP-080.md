# CP-080: input moderation and sanitization

![safety_and_security](../../assets/icons/safety-and-security.svg) ![beginner](../../assets/badges/beginner.svg) ![active](../../assets/badges/active.svg)

**Category:** `safety_and_security` | **Difficulty:** `beginner` | **Confidence:** `high` | **Status:** `active` | **Verified:** `2026-11-11`

## Definition

Screening and normalizing incoming user messages and retrieved tool content for toxic content, PII exposure, encoding tricks, and injection patterns.

## Why It Matters

Pre-inference screening adds a lightweight low-cost defense layer before expensive frontier models process untrusted text.

## How It Works

Dedicated classifiers, regex detectors, and content moderators flag or mask risky spans ahead of core agent planning.

## Example

Redacting payment card numbers and blocking obvious jailbreak signatures prior to support queue routing.

## Common Mistakes

Assuming heuristic input keyword filters alone make an agent immune to semantic prompt injection.
