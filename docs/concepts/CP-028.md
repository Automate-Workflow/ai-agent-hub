# CP-028: delegated tool authentication

![safety_and_security](../../assets/icons/safety-and-security.svg) ![intermediate](../../assets/badges/intermediate.svg) ![active](../../assets/badges/active.svg)

**Category:** `safety_and_security` | **Difficulty:** `intermediate` | **Confidence:** `high` | **Status:** `active` | **Verified:** `2026-11-11`

## Definition

Securely obtaining and scoping user-authorized credentials and OAuth tokens on behalf of an agent acting against external third-party APIs.

## Why It Matters

Delegated authentication avoids sharing static master API keys and ties every external action to a traceable user permission grant.

## How It Works

Authorization servers execute OAuth 2.1 or OIDC flows with PKCE and resource indicators, issuing narrow short-lived tokens to the tool host.

## Example

Obtaining a read-only calendar OAuth token via consent prompt before an assistant inspects meeting availability.

## Common Mistakes

Sharing one service-wide admin credential across all interactive users of a multi-tenant agent.
