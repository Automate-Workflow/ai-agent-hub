# CP-133: API gateway and proxy layer

![evaluation_and_ops](../../assets/icons/evaluation-and-ops.svg) ![intermediate](../../assets/badges/intermediate.svg) ![active](../../assets/badges/active.svg)

**Category:** `evaluation_and_ops` | **Difficulty:** `intermediate` | **Confidence:** `high` | **Status:** `active` | **Verified:** `2026-11-11`

## Definition

Centralized HTTP proxy sitting between agent applications and model providers to enforce auth, rate limits, fallbacks, cost caps, and telemetry.

## Why It Matters

A unified gateway simplifies multi-provider switching, centralized secret isolation, caching, and spend auditing.

## How It Works

Requests target one normalized API endpoint where gateway policies route models, log OpenTelemetry traces, and catch errors.

## Example

Deploying LiteLLM or Helicone in front of team agents for unified OpenAI-compatible routing and spend alerts.

## Common Mistakes

Hardcoding individual vendor API keys and retry loops independently across every microservice.
