# CP-090: hallucination

![evaluation_and_ops](../../assets/icons/evaluation-and-ops.svg) ![beginner](../../assets/badges/beginner.svg) ![active](../../assets/badges/active.svg)

**Category:** `evaluation_and_ops` | **Difficulty:** `beginner` | **Confidence:** `high` | **Status:** `active` | **Verified:** `2026-11-11`

## Definition

Generation of fluent yet factually incorrect, unsupported, or fabricated statements, citations, tool names, or API parameters by a language model.

## Why It Matters

Hallucinations undermine reliability, misinform users, and trigger silent failures when invalid parameters hit downstream systems.

## How It Works

Errors stem from knowledge gaps, ambiguous context, outdated pre-training facts, or weak faithfulness constraints.

## Example

An assistant inventing a plausible-sounding software flag or non-existent legal precedent instead of verifying docs.

## Common Mistakes

Assuming higher model temperature or larger context alone removes hallucination risk without external grounding checks.
