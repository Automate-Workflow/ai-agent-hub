# CP-059: parallel tool execution

![tools_and_actions](../../assets/icons/tools-and-actions.svg) ![intermediate](../../assets/badges/intermediate.svg) ![active](../../assets/badges/active.svg)

**Category:** `tools_and_actions` | **Difficulty:** `intermediate` | **Confidence:** `high` | **Status:** `active` | **Verified:** `2026-11-11`

## Definition

Issuing and running multiple independent tool calls simultaneously within a single agent turn to reduce wall-clock execution time.

## Why It Matters

Parallel execution cuts multi-source retrieval and fan-out investigation latency compared to strictly sequential tool loops.

## How It Works

A model emits multiple tool-call objects in one response, the host executes them concurrently, and returns correlated tool results.

## Example

Reading three independent log files and querying a status endpoint concurrently in one turn.

## Common Mistakes

Parallelizing dependent state-mutating actions that conflict or assume sequential ordering.
