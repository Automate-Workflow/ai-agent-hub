# CP-100: model routing

![models](../../assets/icons/models.svg) ![intermediate](../../assets/badges/intermediate.svg) ![active](../../assets/badges/active.svg)

**Category:** `models` | **Difficulty:** `intermediate` | **Confidence:** `high` | **Status:** `active` | **Verified:** `2026-11-11`

## Definition

Dynamically selecting among strong frontier, specialized reasoning, or compact inexpensive models per task complexity and SLA constraints.

## Why It Matters

Dynamic routing cuts inference spend and boosts responsiveness without sacrificing accuracy on hard reasoning steps.

## How It Works

Routers inspect prompt features, classifier scores, or policy rules to dispatch requests across heterogeneous provider models.

## Example

Using RouteLLM or gateway rules to send simple extraction to compact models and hard coding bugs to frontier models.

## Common Mistakes

Routing sensitive or complex compliance tasks to weak models just to save marginal token fees.
