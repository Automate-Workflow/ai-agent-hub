# CP-087: tracing

![evaluation_and_ops](../../assets/icons/evaluation-and-ops.svg) ![beginner](../../assets/badges/beginner.svg) ![active](../../assets/badges/active.svg)

**Category:** `evaluation_and_ops` | **Difficulty:** `beginner` | **Confidence:** `high` | **Status:** `active` | **Verified:** `2026-11-11`

## Definition

Recording hierarchical parent-child spans capturing every LLM completion, retrieval lookup, guardrail check, and tool invocation within a run.

## Why It Matters

Span trees let developers pinpoint which intermediate step introduced bad retrieval, latency, or corrupted reasoning.

## How It Works

OpenTelemetry-compatible trace contexts propagate trace and span IDs across models, subagents, MCP servers, and APIs.

## Example

Inspecting an interactive trace waterfall showing retrieval latency alongside four iterative tool calls.

## Common Mistakes

Omitting token counts, retrieved document IDs, or model version tags from span attributes.
