# CP-057: streaming events and SSE

![protocols](../../assets/icons/protocols.svg) ![intermediate](../../assets/badges/intermediate.svg) ![active](../../assets/badges/active.svg)

**Category:** `protocols` | **Difficulty:** `intermediate` | **Confidence:** `high` | **Status:** `active` | **Verified:** `2026-11-11`

## Definition

Delivering incremental token chunks, tool status updates, and task progress events continuously from servers to clients over HTTP or WebSockets.

## Why It Matters

Low-latency event streaming keeps interactive users informed during long multi-step reasoning and tool calls.

## How It Works

Servers keep an HTTP Server-Sent Events stream or bidirectional WebSocket open, emitting typed event frames as steps complete.

## Example

Rendering live reasoning progress indicators and token text as an MCP or A2A task executes.

## Common Mistakes

Streaming partial unvalidated tool outputs directly to end-user side effects before final schema checks.
