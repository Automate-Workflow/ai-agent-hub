# CP-134: memory poisoning

![safety_and_security](../../assets/icons/safety-and-security.svg) ![intermediate](../../assets/badges/intermediate.svg) ![active](../../assets/badges/active.svg)

**Category:** `safety_and_security` | **Difficulty:** `intermediate` | **Confidence:** `high` | **Status:** `active` | **Verified:** `2026-11-11`

## Definition

Attack vector wherein malicious inputs corrupt long-term vector stores, user profiles, or episodic memory so future clean sessions behave wrongly.

## Why It Matters

Unlike single-turn prompt injection, poisoned memories persist across sessions and affect later innocent users.

## How It Works

Unvalidated ingested documents or adversarial interactions get written to persistent stores and resurface repeatedly in later queries.

## Example

An attacker injecting false refund policy notes into a shared support memory store to approve fraudulent credits.

## Common Mistakes

Indexing unvetted external chat inputs or third-party attachments directly into shared organizational memory.
