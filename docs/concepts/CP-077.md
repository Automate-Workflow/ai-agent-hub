# CP-077: red teaming

![safety_and_security](../../assets/icons/safety-and-security.svg) ![intermediate](../../assets/badges/intermediate.svg) ![active](../../assets/badges/active.svg)

**Category:** `safety_and_security` | **Difficulty:** `intermediate` | **Confidence:** `high` | **Status:** `active` | **Verified:** `2026-11-11`

## Definition

Adversarial probing of AI agents through simulated attacks to uncover jailbreaks, indirect injections, privilege escalation, and policy failures.

## Why It Matters

Proactive red teaming exposes hidden failure chains across tools and memory before malicious actors exploit them in production.

## How It Works

Security engineers and automated attacker models probe boundary inputs, poisoned documents, and multi-turn scenarios to capture exploits.

## Example

Running adversarial test suites where simulated support tickets embed hidden database export requests.

## Common Mistakes

Testing only isolated single-turn jailbreaks while ignoring multi-turn tool chains and untrusted external data paths.
